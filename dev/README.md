# PDF Grid shared UI

The release at https://gisbi-kim.github.io/pdf-grid/ and the existing `/dev/` URL now use the same UI as the Windows app. Both default to the grid viewer with multiple PDF tabs, merge/split tools, embedded PDF links and bookmarks, text selection, and area image copying.

`dev/` contains the shared shell, tools and local vendor dependencies. `viewer/index.html` contains the embedded grid viewer (including PDF.js). The DEV control displays a nearby version-status popover on hover, focus or click; it no longer navigates to a separate edition. GitHub opens the source repository in a new browser tab or the desktop default browser.

Edit these shared sources, then run `python scripts/sync-ui.py`. This generates the root release entry (using `dev/` as its base URL) and the bundled `desktop-webview2/web/` assets. Native builds run `python scripts/sync-ui.py --check` to reject drift. Do not edit generated UI files directly.

Browser output uses PDF/ZIP downloads and the browser clipboard API. Windows uses native save dialogs and the native image clipboard. Browser clipboard permission and a secure context are required for area copying. Native update controls and OS file associations are available only in the installed app. Local documents are never uploaded; browser storage and the installed app profile remain separate.

Run checks: `node --test dev/tests/*.test.cjs` and `python scripts/sync-ui.py --check`.

Dependencies: pdf-lib 1.17.1, JSZip 3.10.1 and PDF.js 3.11.174, bundled locally with their licenses. Editing inputs are held in memory, limited to 100 MB per split file / merge batch. Encrypted editing inputs are rejected. Page content, size and rotation are copied; document bookmarks, signatures and interactive forms may not survive copying.

Installed app 1.4.4: Ctrl+R / F5 rereads the active PDF from disk while preserving tabs, grid layout, zoom and scroll position. Native-opened PDFs use an opaque source ID; file paths are retained only by the native host. Dragged files use file-system handles where supported. Generated in-memory PDFs are rendered again. With no open PDF the app UI reloads. The web keeps normal browser refresh behavior. A missing, locked or invalid build output keeps the previous document and reports the failure. Reload does not install a new application binary; use the update button for that.

Version 1.4.5 adds a visible **↻ 새로고침** button next to 격자 보기. The installed button shares the shortcut handler and disables while refreshing; the web button performs a normal page reload.

Version 1.5.0 adds `session.js` for installed-app PDF tab/view/history restoration, with IndexedDB snapshots and local-storage metadata. The native host persists source-ID/path mappings and window placement. `viewer/history.js`, `reading-tools.js`, `citations.js`, and `reading.css` provide bounded per-PDF back/forward history, footer labels and offline citation previews; the generator also copies these viewer assets to the native bundle. The web retains its existing last-document storage; full multi-tab persistence is native-only. Native close flushes session state before destruction. No passwords or remote metadata queries are stored/sent. First-time upgrades from 1.4.x require reopening PDFs once.

Version 1.5.1 replaces citation popovers with light, structured paper cards, grouped-citation navigation and explicit DOI/arXiv actions. Extraction excludes aligned review line numbers and accounts for top-of-line destinations. It uses local text and entry-scoped URL annotations only; no metadata service requests. Shared tests cover identifier normalization, entry boundaries and multi-citation groups.

Version 1.5.2 limits page-fit double-click zoom to hand mode. Text selection keeps the browser word-selection behavior and preserves scale/scroll; area-copy mode and PDF links also avoid page-fit zoom. Browser verification uses actual double clicks; native regression checks exercise bubbled double clicks and existing selections.

Version 1.5.3 keeps manual zoom anchored to the reading point even when search highlights remain. Zoom cancels deferred search centering; a queued centering callback must still own the pending search match before moving the viewport. Search submission and explicit previous/next-result actions retain result centering.

Version 1.5.4 moves refresh into a small icon at the left edge of each PDF tab. Clicking it refreshes that tab without changing the active tab; native Ctrl+R/F5 still refreshes the active tab. Each refreshing tab shows busy state and temporarily disables its refresh/close controls. The web icon refreshes only that document from its file-system handle when available or its retained File, including browser-restored files; it no longer reloads the entire web page. Browser Ctrl+R/F5 retain their usual page-reload behavior.

Version 1.5.5 binds Ctrl+W in the installed shell and its PDF iframes to the active tab close button, including search-field focus. It closes one tab per key press, respects busy/refresh/update guards, selects an adjacent tab and retains one blank tab after the last PDF. The browser edition leaves its reserved Ctrl+W behavior alone. Existing tab/cache removal is reused. Native CI sends real OS Ctrl+W from PDF, ribbon and search focus and verifies the last-tab behavior.

Version 1.5.6 adds `tab-menu.js`: right-click a PDF tab title, or use Shift+F10/ContextMenu, to open its menu. The first command copies its absolute source path through the native host. Right-clicking a background tab leaves the active PDF unchanged. Escape, outside clicks and window changes dismiss the menu. Source IDs select already-authorized paths; the native host writes Unicode clipboard text without returning the path to JavaScript. Web tabs, empty tabs and PDFs without a native source path show a disabled command with an explanation; file names and browser file handles do not establish an absolute path.

Version 1.6.0 adds a bounded, in-memory stack of the last 20 closed PDF tabs. Native Ctrl+Shift+T and shared toolbar/context-menu actions restore their original order, File snapshot/source handle, view and navigation history; native/handle sources are reread with cached fallback. Closed history is cleared when the app/page exits, does not store passwords, and does not change removal from the persistent open-tab cache. Side-by-side viewing uses two live tab iframes with an active pane, independent scroll/zoom, file-name headings and a draggable/keyboard separator (25–75%). Selecting a third tab replaces the active pane; closing either visible tab returns the other to single view. Layout changes preserve normalized view/relative zoom, and native metadata optionally stores the split pair and ratio without changing the v1 session schema. Browser shortcuts remain browser-owned; toolbar/menu actions work on the web. Session flush waits for the final layout before saving.
With 1.6.1, the installed app reads saved tab names, order and view metadata without loading PDF files. A PDF passed to the app at startup opens first. An ordinary launch opens only the saved visible tab or split pair. Selecting a saved background tab reads its source or cached snapshot and restores the view and navigation history.
